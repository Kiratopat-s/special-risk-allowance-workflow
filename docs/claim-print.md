# ใบคำขอเบิกรายบุคคลสำหรับพิมพ์

เปิดจาก “ดูตัวอย่างใบคำขอ” ในรายละเอียดคำขอ หรือ “ดูตัวอย่างใบคำขอทั้งชุด” ในรายละเอียดชุดรวบรวมรายเดือน แต่ละคำขอเริ่มกระดาษใหม่เสมอ ปุ่ม “พิมพ์สรุปรายเดือน” ยังใช้แบบสรุปเดิม

## การพิมพ์

1. รอฟอนต์ TH Sarabun ภาพ และการแบ่งหน้าให้เสร็จ ตรวจจำนวนคำขอ จำนวนหน้า และคำเตือนข้อมูลขาด
2. กด “พิมพ์ / บันทึก PDF” เลือก A4 แนวนอน ขนาด 100% และปิดหัว/ท้ายกระดาษของเบราว์เซอร์ ใน Safari ต้องเลือก Landscape ในหน้าต่างพิมพ์ด้วย
3. ตรวจจำนวนหน้าในหน้าต่างพิมพ์ให้ตรงกับ Preview แล้วเลือกเครื่องพิมพ์หรือ Save as PDF

ไม่มีการเปิดหน้าต่างพิมพ์อัตโนมัติและไม่มีการเก็บ PDF บนเซิร์ฟเวอร์ ชุดว่างไม่มีปุ่มพิมพ์ กรณีทรัพยากรโหลดไม่สำเร็จจะแจ้งข้อผิดพลาดพร้อมปุ่มลองใหม่

## ข้อมูลและสิทธิ์

- รายคำขอ: `/expense-claim-document/[id]/print` ตรวจสิทธิ์ `EXPENSE_CLAIM:READ` กับเจ้าของคำขอที่ service
- ทั้งชุด: `/monthly-request-collection/[id]/claims/print` ใช้ขอบเขตการมองเห็นชุดเดิม ทั้งเจ้าของชุด สถานะร่าง และขั้นตรวจสอบ ก่อนอ่านคำขอทั้งหมดจากฐานข้อมูล ไม่ผูกกับ pagination ของตาราง
- ตัดคำขอที่ยกเลิก เรียงตามรหัสพนักงาน ชื่อ นามสกุล และ ID คำสั่งเรียงตามวันเริ่มงานและ ID
- ใช้ตำแหน่งผู้เบิกที่บันทึกตอนยื่น ชื่อ/ตำแหน่งผู้ควบคุมจากคำสั่ง และสังกัดจากผู้ใช้ที่เชื่อมกับคำสั่ง ช่องที่ไม่มีข้อมูลเว้นว่าง
- ลายเซ็นมาจากรายการรับรองที่ตรงทั้งคำขอและคำสั่ง มีเวลารับรองและภาพที่บันทึกไว้ ไม่อ่านลายเซ็นประจำตัวปัจจุบันหรือส่ง token รับรองไปยังหน้า Preview
- วันปฏิทินใช้ UTC กับข้อมูล date-only แสดงภาษาไทยและปี พ.ศ. ทำเครื่องหมายเฉพาะวันที่เลือกในเดือนนั้น แจ้งเตือนวันที่ซ้ำ/อยู่นอกเดือนและจำนวนวันไม่ตรง โดยไม่แก้ค่าที่บันทึก
- แสดงสถานะทุกหน้า รายการที่ไม่ใช่ `APPROVED` มีข้อความ “ยังไม่อนุมัติ”

## การจัดหน้าและข้อจำกัด

เทมเพลตร่วมอยู่ใน `components/claim-print/` และตัวแบ่งหน้าอยู่ใน `lib/ui/claim-print-pagination.ts` วัดความสูงหลังฟอนต์และภาพพร้อม จำกัดไม่เกิน 5 คำสั่งต่อหน้าและย้ายแถวพร้อมลายเซ็นทั้งแถว หมายเหตุยาวแยกบนขอบเขตตัวอักษรภาษาไทยโดยเก็บข้อความครบ

พื้นที่แบบฟอร์มกว้าง 281 มม. สูง 189 มม. บน A4 แนวนอนที่มีขอบบน/ล่าง 10 มม. ซ้าย/ขวา 8 มม. เผื่อความสูง 1 มม. ป้องกัน Safari สร้างหน้าว่างจากการปัดเศษ หากคำสั่งหนึ่งแถวยาวเกินพื้นที่ทั้งหน้า จะหยุดและแจ้งให้ตรวจข้อมูลแทนการตัดข้อความหรือตัดลายเซ็นออกจากแถว

## ผลตรวจรับด้วยข้อมูลจำลอง (14 กันยายน 2569)

- ทดสอบสิทธิ์ผ่าน URL โดยตรง เจ้าของ/ผู้อ่านทั้งหมด/ผู้ไม่มีสิทธิ์ และข้อจำกัดชุดรายเดือน
- ทดสอบลายเซ็นตรงคู่คำขอ-คำสั่ง รับรองบางส่วน รับรองแล้วไม่มีภาพ และไม่อ่านลายเซ็นประจำตัวมาทดแทน
- ทดสอบเดือน 28/29/30/31 วัน วันซ้ำ รายการเก่า คำสั่งคร่อมเดือน แถว 0/1/5/เกิน 5 และข้อความยาว
- ทดสอบรอทรัพยากร โหลดล้มเหลว ลองใหม่ ไม่พิมพ์เอง เนื้อหาทับท้ายกระดาษ ชุดว่าง และปุ่มเปิด Preview
- Chrome: PDF รายคำขอ 1 หน้า และชุด 3 คำขอ 6 หน้า เป็น A4 แนวนอน
- Safari บน macOS: Save as PDF ชุดเดียวกัน 6 หน้า A4 แนวนอน ที่ 100% ปิดหัว/ท้ายเบราว์เซอร์ ตรวจภาพทุกหน้าแล้ว
- PDF และภาพตัวอย่างอยู่ใน `output/pdf/` (ไฟล์ตรวจรับที่ไม่ commit) ใช้ชื่อบุคคลและภาพลายเซ็นจำลองทั้งหมด

คำสั่งตรวจสอบ: `bun run test`, `bun run lint`, `bunx tsc --noEmit` และ `bun run build --webpack` ผ่าน การรัน `bun run build` แบบ Turbopack ในสภาพแวดล้อมนี้ติดข้อจำกัดสร้าง process/เปิด port ของ CSS worker จึงใช้ webpack ตรวจ production build

ยังต้องตรวจใน Edge ซึ่งไม่ได้ติดตั้งบนเครื่องนี้ และทดสอบพิมพ์ A4 จริงที่ 100% เทียบขนาด/ขอบกับเอกสารต้นฉบับ รวมถึงตรวจด้วยบัญชีและข้อมูลจริงในสภาพแวดล้อมตรวจรับก่อนใช้งานจริง
