# Dependency Security Upgrade Plan

## Current State
- **55 vulnerabilities**: 3 critical, 26 high, 23 moderate, 3 low
- **Package manager**: Bun 1.3.14
- **Stack**: Next.js 16, React 19, TypeScript 5.9, Prisma 7.8, next-auth 5 beta, Tailwind CSS 4

## Key Finding: Zero Source Code Changes Required

All 55 vulnerabilities are resolved through version bumps only. No refactoring needed because:
- `next-auth@5.0.0-beta.32` is a security-only release with identical API
- `nodemailer` v9 breaking changes (TLS cert validation) don't affect SMTP-only usage
- All other upgrades are minor/patch versions

---

## Phase 1: Critical + High Security Fixes

**Fixes**: 3 critical + ~20 high + ~12 moderate vulnerabilities

### Changes in `package.json`:
```
next-auth:  ^5.0.0-beta.30  →  ^5.0.0-beta.32  (fixes 3 critical auth vulns)
next:      ^16.2.10         →  ^16.3.2          (fixes SSRF, middleware bypass, DoS)
nodemailer: ^7.0.7          →  ^9.0.1           (fixes disableFileAccess bypass)
eslint-config-next: 16.2.10 →  16.3.2           (match next version)
```

### Why no code changes:
- `next-auth` beta.32: security-only patch, all 11 import sites unchanged
- `next` 16.3.2: minor version, App Router API stable
- `nodemailer` 9.x: `createTransport()` and `sendMail()` APIs unchanged; breaking changes only affect HTTP content fetching (not used)

### Verification:
```bash
bun install && bun audit && bun run build && bunx tsc --noEmit
```
Manual: auth flow, email sending, session persistence

## Phase 3: Dependency Hygiene

### 3.1 Move `@types/nodemailer` from dependencies to devDependencies
- `@types/*` only needed at compile time, bloats production node_modules

### 3.2 Add `dotenv` as devDependency
- `prisma.config.ts` imports `dotenv/config` but it's not declared
- Currently works as transitive dep (fragile)
- devDependency because prisma.config.ts only runs via Prisma CLI

### Verification:
```bash
bun install && bun audit && bun run build
bunx prisma validate && bunx prisma generate
```

